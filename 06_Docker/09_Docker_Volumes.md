# 💾 Docker Volumes

Docker Volumes provide **persistent storage** for containers. By default, data stored inside a container is lost when the container is removed. Volumes solve this problem by storing data outside the container's writable layer, allowing it to persist across container restarts and recreations.

# What are Docker Volumes?

A Docker Volume is a managed storage location used to persist data generated by containers.

Unlike container storage, Docker Volumes remain available even after a container is deleted.

Example

```text
Container
      │
      ▼
Docker Volume
      │
      ▼
Host Storage
```

---

# Why Use Volumes?

Without Volumes

```text
Container
      │
Application Data
      │
Container Deleted
      │
❌ Data Lost
```

With Volumes

```text
Container
      │
Docker Volume
      │
Host Storage
      │
Container Deleted
      │
✅ Data Still Exists
```

# How Docker Volumes Work

```text
MySQL Container
       │
Writes Data
       │
Docker Volume
       │
/var/lib/docker/volumes/
       │
Host Machine
```

When the MySQL container is removed, the database files remain in the volume.

# Types of Docker Storage

| Storage Type | Description |
|--------------|-------------|
| Volume | Docker-managed persistent storage |
| Bind Mount | Maps a host directory into a container |
| tmpfs Mount | Temporary in-memory storage |

# Docker Volume Commands

| Command | Description |
|----------|-------------|
| `docker volume create` | Create a volume |
| `docker volume ls` | List all volumes |
| `docker volume inspect` | View volume details |
| `docker volume rm` | Remove a volume |
| `docker volume prune` | Remove unused volumes |
| `docker run -v` | Mount a volume into a container |
| `docker run --mount` | Modern mount syntax |

# Practical Examples

## Create Volume

Purpose

Create a Docker-managed volume.

Syntax

```bash
docker volume create my-volume
```

Expected Output

```text
my-volume
```

Use Case

Create persistent storage for MySQL or PostgreSQL databases.

---

## List Volumes

```bash
docker volume ls
```

Expected Output

```text
DRIVER    VOLUME NAME

local     my-volume
```

Use Case

View all available Docker volumes.

---

## Inspect Volume

```bash
docker volume inspect my-volume
```

Expected Output

```json
[
  {
    "Name": "my-volume",
    "Driver": "local",
    "Mountpoint": "/var/lib/docker/volumes/my-volume/_data"
  }
]
```

Use Case

Identify where Docker stores persistent data.

---

## Remove Volume

```bash
docker volume rm my-volume
```

Expected Output

```text
my-volume
```

Use Case

Delete unused persistent storage.

---

## Remove Unused Volumes

```bash
docker volume prune
```

Expected Output

```text
Deleted Volumes:
...
```

Use Case

Clean up orphaned volumes.

---

## Mount Volume

```bash
docker run -d \
-v my-volume:/var/lib/mysql \
mysql
```

Use Case

Persist MySQL database files.

---

## Using --mount

```bash
docker run -d \
--mount source=my-volume,target=/var/lib/mysql \
mysql
```

This is the preferred syntax because it is more readable and flexible.

# Bind Mount vs Volume

| Volume | Bind Mount |
|----------|------------|
| Managed by Docker | Managed by Host OS |
| Portable | Host-specific |
| Easier Backup | Manual Management |
| Preferred for Production | Preferred for Development |

Example Bind Mount

```bash
docker run \
-v /home/user/app:/app \
node
```

Host directory

```text
/home/user/app
```

becomes

```text
/app
```

inside the container.

# Anonymous Volumes

Docker can create volumes automatically.

Example

```bash
docker run \
-v /var/lib/mysql \
mysql
```

Docker generates a random volume name.

Generally used for temporary storage.

---

# Named Volumes

Recommended approach.

Example

```bash
docker volume create mysql-data
```

Mount

```bash
docker run \
-v mysql-data:/var/lib/mysql \
mysql
```

Benefits

- Easy backup
- Easy restore
- Easy migration
- Easy management

# Common Mistakes

❌ Storing database data inside the container.

❌ Deleting volumes accidentally.

❌ Confusing Bind Mounts with Volumes.

❌ Using anonymous volumes unintentionally.

❌ Forgetting to back up important volumes.

---

# Best Practices

- Use named volumes for databases.
- Use bind mounts for application source code during development.
- Regularly back up production volumes.
- Remove unused volumes using `docker volume prune`.
- Avoid storing critical data inside container filesystems.

# Interview Questions

## 1. What is a Docker Volume?

A Docker-managed persistent storage mechanism that allows data to survive container deletion.

---

## 2. Why are volumes required?

Containers are ephemeral. Volumes ensure application data persists even when containers are recreated.

---

## 3. Difference between Volume and Bind Mount?

| Volume | Bind Mount |
|----------|------------|
| Managed by Docker | Managed by Host OS |
| Portable | Host-dependent |
| Recommended for Production | Mainly used in Development |

---

## 4. What is an Anonymous Volume?

A Docker-created volume with an automatically generated name, typically used for temporary storage.

---

## 5. Which command lists all Docker volumes?

```bash
docker volume ls
```

---

## 6. Which mount syntax is recommended?

```bash
--mount
```

because it is explicit, readable, and supports more options than `-v`.

# Summary

Docker Volumes provide persistent storage independent of container lifecycles, making them essential for stateful applications such as databases, monitoring tools, and CI/CD servers. By using named volumes and proper backup strategies, DevOps engineers can ensure reliable data persistence while keeping container deployments portable and maintainable.
